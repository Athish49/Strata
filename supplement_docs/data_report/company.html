S16 Join Guide to Regulatory Side [live-db tested]

code_section_id is NULL everywhere — all joins must use citation_raw = code_sections.citation. All 5 queries tested live with results noted.
(a) All company clauses citing a given code_section (any snapshot)
SELECT c.clause_id, c.doc_id, c.clause_role, c.assessable,
       cc.citation_raw, cc.source_system,
       cs.id AS code_section_id, cs.snapshot_date, cs.status
FROM   company.clauses c
JOIN   company.clause_citations cc ON cc.clause_pk = c.clause_pk
JOIN   public.code_sections cs
       ON  cs.citation = cc.citation_raw
       AND cs.snapshot_date = '2024-12-31'   -- Snapshot 1
WHERE  cs.citation = :section_citation       -- e.g. '170 IAC 4-1-16'
ORDER  BY c.doc_id, c.clause_id;
-- DO NOT join on cc.code_section_id (all NULL)

result [live-db] 5 rows for 170 IAC 4-1-24: RPL-SAF-PRO-009:2, RPL-CMP-REG-001:12.1, RPL-CS-PRO-004:T4-1, T4-2, T4-3

(b) All parameters tied to a given regulatory section
SELECT cp.name, cp.value_text, cp.unit, cp.kind, cp.value_source,
       cc.citation_raw, cs.id AS code_section_id
FROM   company.clause_parameters cp
JOIN   company.clauses c ON c.clause_pk = cp.clause_pk
JOIN   company.clause_citations cc ON cc.clause_pk = c.clause_pk
JOIN   public.code_sections cs
       ON  cs.citation = cc.citation_raw
       AND cs.snapshot_date = '2024-12-31'
WHERE  cs.citation = :section_citation
  AND  cp.name IS NOT NULL;
-- supported_by_citation_pk is often NULL; clause-level join above is safer

result [live-db] Clause-level join returns parameters for most sections with named params.

(c) Clauses reachable via restates and term_usages
WITH seed AS (
    SELECT c.clause_pk FROM company.clauses c
    JOIN company.clause_citations cc ON cc.clause_pk = c.clause_pk
    JOIN public.code_sections cs ON cs.citation = cc.citation_raw
                               AND cs.snapshot_date = '2024-12-31'
    WHERE cs.citation = :section_citation
),
restates AS (
    SELECT cl.to_clause_pk AS clause_pk FROM company.clause_links cl
    JOIN seed s ON s.clause_pk = cl.from_clause_pk WHERE cl.link_type = 'restates'
),
term_reach AS (
    SELECT tu.clause_pk FROM company.term_usages tu
    JOIN company.defined_terms dt ON dt.term_pk = tu.term_pk
    JOIN seed s ON s.clause_pk = dt.definition_clause_pk
)
SELECT DISTINCT c.clause_id, c.doc_id, c.clause_role, src
FROM (SELECT clause_pk, 'restates' AS src FROM restates
      UNION ALL SELECT clause_pk, 'term_usage' AS src FROM term_reach) reach
JOIN company.clauses c ON c.clause_pk = reach.clause_pk;

result [live-db] Tested: RPL-CMP-REG-001:2.3 restates RPL-CMP-REG-001:4.3 (conf=0.62). restates are bidirectional by design.

(d) Documents whose scope contains a rule
SELECT ds.doc_id, ds.scope_key, ds.clause_count,
       dv.version, dv.effective_date
FROM   company.document_scope ds
JOIN   company.document_versions dv ON dv.version_id = ds.version_id
WHERE  ds.scope_level = 'rule'
  AND  ds.scope_key  = :rule_citation  -- e.g. '170 IAC 4-1'
